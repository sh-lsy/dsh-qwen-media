# 提示词工程指南（ distilled from 官方 Prompt 指南与模型文档）

## 图像

- 基础：主体 + 场景 + 风格 + 构图/光影。描述越具体越稳。
- 文字渲染/海报/图表/UI（qwen-image-3.0-pro 强项）：把要出现的文字用引号逐字写出，说明字号层级与位置，如"标题'夏日特惠'居中、副标题小字居下"。
- 编辑指令（I2I）：直接说改什么、保留什么，如"把背景换成海边黄昏，人物与服装保持不变"。多图时按顺序指代"图1/图2"。
- 组图（wan2.7 `--sequential`）：在 prompt 中按"第一张…第二张…"列出每张内容，保持主体/风格统一的总述在前。
- 反向提示词（仅 qwen）：`--negative "低分辨率、模糊、多余的手指、文字错乱"`。
- 简单提示词可依赖 prompt_extend（默认开）；需要精确控制时 `--no-extend`。
- 长度：qwen 建议 ≤4500 Token；wan text ≤5000 字符。

## 视频

- 基础公式：**主体 + 场景 + 运动**。运动写清动作过程与镜头运动（"镜头缓慢推进""固定镜头"）。
- 多镜头（wan3.0/wan2.7）：`总体描述 + 镜头序号 + 时间戳 + 分镜内容`，如"镜头1[0-3秒] 全景：雨夜街头；镜头2[3-6秒] 特写：…"。想要单镜头就写"生成单镜头视频"。
- 声音公式（原生音频模型）：主体+场景+运动+**声音描述**。人声=台词+情绪+语调+语速+音色；音效=动作对应声；BGM=风格。例："他压低声音说：'别出声'，远处雷声渐近，悬疑弦乐铺底"。
- 口型同步：wan3.0 传 `--audio-url`（wav/mp3、2–30s、≤15MB）；音频长于 duration 截断、短于则后段无声。
- 参考生视频：
  - happyhorse-r2v：`[Image 1] 中身着红旗袍的女性走进 [Image 2] 的房间，回头微笑说："你来了。"`（顺序=--ref 顺序）
  - wan：`图 1 的猫在图 2 的房间里玩耍`（英文 `Image 1`/`Video 1`，空格分隔）；音色参考用参考视频。
- 首帧生视频（i2v）：prompt 描述"动起来之后"的运动与声音，不要复述首帧静态内容。
- 反向提示词（仅 wan3.0）：`--negative "低分辨率、错误、最差质量、残缺、多余的手指、比例不良"`（≤500字符）。
- 长度：happyhorse ≤2500 中文字符；超出自动截断。

## 审核拦截改写

触发 DataInspectionFailed 等审核错误时：去除真实人名/品牌/暴力/敏感意象，改用泛化描述（"一位穿红裙的舞者"而非真实明星），重试一次；仍失败则如实报告并建议换主题。

## 成本提示措辞

视频按秒×分辨率计费：向用户确认时给出"模型 / 分辨率 / 秒数"三要素，如"wan3.0-video / 1080P / 15s（约为 720P/5s 的 6 倍像素秒）"。失败任务不计费。
